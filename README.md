# 2026 年度司法大事記｜上線與 Google 表單嫁接說明

這是民間司改會「年度司法大事記」網站的正式上線版本。網站是純靜態網頁，放在 GitHub Pages 上免費運作；民眾送出的圈選清單會直接寫進一份 Google 表單，資料由司改會在 Google 試算表裡統計，不對外公開。

---

## 整體運作方式

```
民眾在網站圈選、送出清單
        │  （網頁在背景把圈選的事件代碼送到 Google 表單，就像有人填了表單一樣）
        ▼
Google 表單收到一筆回覆：「03, 07, 10」
        │
        ▼
Google 試算表自動多一列 → 「統計」工作表即時算出每件事被幾個人圈選
        │
        ▼
結果公布時，把統計結果貼回網站資料檔，網站就會顯示年度排名
```

民眾在網站上看不到即時結果，只會看到自己的清單、關注類型和分享圖卡。

## 檔案說明

| 檔案 | 用途 | 需要改嗎 |
| --- | --- | --- |
| `index.html` | 網站本體 | 不用 |
| `assets/config.js` | 網站設定：年度、截止日、Google 表單連線 | **上線前要改** |
| `data/events.js` | 事件內容、圖片、相關新聞、年度結果 | 內容更新時改 |

## 第一部分：上傳到 GitHub

1. 到 [github.com](https://github.com) 登入司改會帳號（沒有的話先註冊）。
2. 右上角「＋」→「New repository」。
   - Repository name 建議用英文小寫，例如 `judicial-review-2026`。
   - 選 **Public**（免費帳號的 GitHub Pages 需要公開儲存庫；網站本來就是公開的，資料庫裡沒有任何民眾資料）。
   - 按「Create repository」。
3. 在新的儲存庫頁面點「uploading an existing file」，把**解壓縮後資料夾裡的所有檔案和資料夾**一起拖進去（是資料夾裡面的東西，不是外層資料夾本身）。
   - `.nojekyll` 是隱藏檔，Mac 可按 `Command + Shift + .` 顯示後一起拖入。
4. 最下方按「Commit changes」。
5. 到儲存庫的「Settings」→ 左側「Pages」。
   - Source 選「Deploy from a branch」。
   - Branch 選 `main`，資料夾選 `/ (root)`，按「Save」。
6. 等 1 到 10 分鐘，同一頁上方會出現網址，例如：
   `https://你的帳號.github.io/judicial-review-2026/`
7. 把這個網址填進 `assets/config.js` 的 `siteUrl`（分享圖卡底部會印出這個網址）。

> 之後要修改任何檔案：在 GitHub 上點該檔案 →右上角鉛筆圖示編輯 →「Commit changes」，網站約 1 分鐘後更新。

**（選用）使用司改會自己的網域**，例如 `review.jrf.org.tw`：在 Settings → Pages → Custom domain 填入網域，再請管理網域的人新增一筆 CNAME 記錄，指向 `你的帳號.github.io`。

## 第二部分：建立 Google 表單

建議用司改會的公務 Google 帳號建立，方便日後交接。

### 1. 新增表單與題目

1. 到 [forms.google.com](https://forms.google.com) 建立空白表單，標題例如「2026 年度司法大事記（網站專用）」。
2. **第一題：圈選事件**
   - 題型選「**核取方塊**」，題目名稱「圈選事件」，開啟「**必填**」。
   - 選項：打開 `setup.html` 第 2 步，按「複製選項」，回到表單點第一個選項的輸入框貼上，會自動變成 01 到 22 共 22 個選項。
   - 右下角「⋮」→「回應驗證」→ 選「**最多選取**」，數字填 **5**。（網站本身已經會擋超過 5 件，這是第二道保險。）
3. **第二題（選填）：關注類型**
   - 題型選「**簡答**」，題目名稱「關注類型」，**不要**設為必填。
   - 這一題會記錄每個人的關注類型（例如「人權守門人」），方便日後分析。不需要可以不建。
4. 整份表單**只能有一個區段**，不要加其他必填題目，否則網站送出會失敗。

### 2. 表單設定（很重要，設錯會收不到資料）

點表單上方的「設定」分頁：

| 設定 | 要設成 | 原因 |
| --- | --- | --- |
| 收集電子郵件地址 | **不收集** | 收集信箱需要登入，網站送不進去 |
| 限制回覆次數為 1 次 | **關閉** | 需要登入 Google 帳號，網站送不進去 |
| 僅限貴機構的使用者填寫（Google Workspace 帳號才有） | **關閉** | 同上，會擋掉一般民眾 |
| 允許回覆者編輯回覆 | 關閉 | 不需要 |

最後確認表單右上角的「發布」或「接受回覆」是開啟狀態。

### 3. 連結試算表

表單上方「回覆」分頁 →「連結至試算表」→「建立新試算表」。之後每一筆回覆都會自動出現在這份試算表裡。

## 第三部分：嫁接網站與表單

用 `setup.html` 小幫手操作，不需要看程式碼。

1. 在瀏覽器打開 `https://你的網址/setup.html`（或直接在電腦上雙擊解壓縮資料夾裡的 `setup.html`）。
2. 回到 Google 表單編輯畫面，右上角「⋮」→「**取得預先填入的連結**」。
3. 在跳出的表單裡：「圈選事件」勾選 **01**；「關注類型」隨便填，例如「測試」。
4. 按最下方「取得連結」→「複製連結」。
5. 回到 `setup.html` 第 3 步，把連結貼進輸入框，會立刻顯示一段設定，按「複製設定」。
6. 到 GitHub 打開 `assets/config.js` → 鉛筆圖示編輯 → 把 `googleForm: { …… }` 那一整段換成剛剛複製的內容 →「Commit changes」。

如果想手動設定，三個值的來源如下：

```
預先填入的連結：
https://docs.google.com/forms/d/e/1FAIpQLSxxxx/viewform?usp=pp_url&entry.123456789=01&entry.987654321=測試
                                 └──────┬──────┘                     └─────┬─────┘      └─────┬─────┘
                       action = 把 viewform?… 換成 formResponse      picksEntry          personaEntry
```

## 第四部分：測試

1. **小幫手測試**：在 `setup.html` 第 4 步按「送出測試」，再到表單「回覆」分頁確認多了一筆「01, 02」。
2. **實際網站測試**：等 GitHub 更新後（約 1 分鐘），用手機和電腦各實際圈選、送出一次，確認試算表有收到。
3. **超過 5 件測試**：圈 6 件以上按送出，應該跳出「最多只能圈 5 件」的提醒，且試算表不會多出資料。
4. 測試完，到試算表把測試資料整列刪除（或在表單「回覆」分頁刪除個別回覆）。

> 小提醒：網站已送出的瀏覽器會記住「已送出」，同一個瀏覽器無法再送第二次。要重複測試時，請用無痕視窗。

---

## 第五部分：在試算表統計結果

1. 在試算表下方按「＋」新增工作表，命名「統計」。
2. 到 `setup.html` 第 2 步按「複製對照表」，貼到「統計」工作表的 A1（會填入 A 代碼、B 事件、C 分類）。
3. 依 `setup.html` 第 5 步，把公式貼到指定儲存格：
   - **D2**：這件事被幾個人圈選，選取 D2 後往下拉到最後一件。
   - **F1**：總共幾個人送出。
   - **E2**：網站用的格式，往下拉。
   - **F2**：合併成一行，公布結果時使用。
4. 可以用 D 欄排序（資料 → 排序範圍）看目前排名。這份試算表請只分享給內部同仁。

## 日常維護

**補圖片**：圖片放進 `images/`（建議 3:2、寬 1200px、每張 300KB 以內），在事件的 `image` 填 `"images/2026-01.jpg"`。

**補事件回顧詳細版**：在事件的 `full` 填入文字，換段用 `\n`，例如：

```js
full:"第一段內容。\n第二段內容。",
```

**新聞與時間軸**：每則新聞一行，要指定為重點新聞就加 `key:true`：

```js
{date:"2026/03/25", media:"中央社", title:"新聞標題", url:"https://www.cna.com.tw/……", key:true},
```

- 重點新聞在時間軸上會用紅色粗體醒目標示，事件的發生日期也以它為準。
- 都沒標 `key` 時，以第一則新聞為準。
- 標了兩則以上，這件事會在票選頁時間軸上出現在每個重點日期，第二次以後以灰色精簡卡片呈現，圈選共用。
- 新媒體的標籤顏色在 `data/events.js` 最上方的 `JRF_MEDIA` 新增，沒列到的會顯示灰色。

**截止與公布結果**

1. 截止時間一到，網站會自動停止接受送出；同時請到 Google 表單關閉「接受回覆」。
2. 公布時，打開 `data/events.js` 的 2026 年度，修改三個地方：

```js
status: "closed",
jrfTop: ["07","19","10","04","17","01","12","03","20","05"],   // 司改會評選，依名次排列的事件代碼
final: { voters: 3125, votes: { "01": 812, "02": 640, …… } }    // voters 用「統計」F1 的人數；votes 直接貼「統計」F2 的內容
```

3. 存檔後，「年度結果」和「歷年回顧」會自動顯示「大家心中的年度大事」與「司改會評選」的對照，以及完整排名。

**下一年度（2027）**

1. 在 `data/events.js` 的 `window.JRF_DATA` 裡新增 `2027: { status:"open", jrfTop:null, final:null, events:[ …… ] }`，2026 的資料保留，歷年回顧會自動出現 2027 分頁。
2. `config.js` 的 `year` 改成 2027，並更新 `deadline`、`announce`。
3. 建一份新的 Google 表單，重新用 `setup.html` 嫁接一次。

## 常見問題

**送出後試算表沒有資料？**
依序檢查：表單設定是否關掉了「收集電子郵件」「限制回覆 1 次」「僅限貴機構」；表單是否還在「接受回覆」；`config.js` 的 `action` 結尾是不是 `formResponse`；表單選項是不是 `01`、`02` 這種兩位數代碼（不能是 `1`、`2`，也不能加標題）；有沒有其他必填題目。

**為什麼網站沒辦法確認送出成功？**
Google 表單不允許其他網站讀取它的回應，所以網站只能確認「有送出去」，無法確認「已寫入」。這也是為什麼上線前一定要實際測試。

**可以防止同一個人重複送出嗎？**
網站會記住同一個瀏覽器已送出過，但換瀏覽器或用無痕視窗仍可再送。Google 表單的「限制 1 次」需要民眾登入 Google 帳號，會大幅降低參與意願，所以不建議開啟。結果頁與關於頁都已說明，這是參與者的關注排行，不是具代表性的抽樣民調。

**修改了事件標題，已收到的資料會亂掉嗎？**
不會。表單只記錄事件代碼，標題可以隨時修改。但**不要更改已上線事件的代碼**，也不要刪除表單裡的選項。

**表單選項的順序重要嗎？**
不重要，但選項文字必須和事件代碼完全一樣。
