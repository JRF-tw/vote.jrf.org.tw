# 年度司法大事記｜部署與 Google 表單嫁接說明（維護者用）

這份文件給負責維護網站的司改會同仁。網站是純靜態網頁，放在 GitHub Pages（`JRF-tw/vote.jrf.org.tw`，網址 https://vote.jrf.org.tw/）；民眾在網站視窗填寫 Email 後，網站會直接把圈選清單與 Email 傳送到 Google 表單，資料由司改會在 Google 試算表裡統計，不對外公開。

> **關於 `setup.html`（表單嫁接小幫手）**：它的「送出測試」按鈕任何人都能按，會往正式表單寫入測試資料，所以已從網站移除。需要時從 git 歷史取回，在自己電腦上雙擊開啟使用，用完**不要 commit**：
>
> ```
> git checkout 368cc01 -- setup.html
> # 用完後
> git rm --cached setup.html && rm setup.html
> ```
>
> 舊版 `setup.html` 未包含目前的 Email 欄位設定，請以本文第三部分為準；第 2 步（複製選項、對照表）和第 5 步（統計公式）仍可使用。

---

## 整體運作方式

```
民眾在網站圈選，按「完成我的清單」
        │
        ▼
在網站視窗填寫 Email，按「送出我的清單」
        │  Email 必填、檢查基本格式；網站直接在背景送出，不開啟 Google 表單
        ▼
Google 表單收到一筆回覆：電子郵件 + 「03, 07, 10」
        │
        ▼
Google 試算表自動多一列 → 「統計」工作表即時算出每件事被幾個人圈選
        │
        ▼
結果公布時，把統計結果貼回網站資料檔，網站就會顯示年度排名
```

民眾在網站上看不到即時結果，只會看到自己的清單、關注類型和分享圖卡。

## 第一部分：開啟 GitHub Pages

儲存庫已經在 `JRF-tw/vote.jrf.org.tw`。

1. 儲存庫「Settings」→「General」最下方，把可見度改成 **Public**（免費方案的 GitHub Pages 需要公開儲存庫；網站本來就是公開的，儲存庫裡沒有任何民眾資料）。
2. 「Settings」→ 左側「Pages」：
   - Source 選「Deploy from a branch」。
   - Branch 選 `main`，資料夾選 `/ (root)`，按「Save」。
   - Custom domain 會自動讀到 `CNAME` 檔裡的 `vote.jrf.org.tw`。
3. 請管理 `jrf.org.tw` 網域的人新增一筆 DNS 記錄：`vote` CNAME 指向 `jrf-tw.github.io`。
4. HTTPS：目前 `vote.jrf.org.tw` 經過 Cloudflare 代理（DNS 記錄是橘色雲朵），由 Cloudflare 提供 HTTPS，GitHub 的「Enforce HTTPS」無法勾選，這是正常的。Cloudflare 的 SSL/TLS 模式請設「Full」，不要用「Flexible」。如果改成不經過 Cloudflare（灰色雲朵），就要回 Pages 設定勾選「Enforce HTTPS」。
5. `assets/config.js` 的 `siteUrl` 已填 `https://vote.jrf.org.tw/`。若網址改變，要一起改：`siteUrl`、`CNAME`、`index.html` 裡所有 `https://vote.jrf.org.tw/`（canonical、`og:url`、`og:image`、結構化資料）、`robots.txt`、`sitemap.xml`。

> 之後要修改任何檔案：在 GitHub 上點該檔案 →右上角鉛筆圖示編輯 →「Commit changes」，網站約 1 分鐘後更新。

### GitHub 與網域安全設定（請在開啟 Pages 前完成）

能推送到 `main` 的人就能改網站內容，所以要保護的是帳號和網域：

- **驗證網域**：組織 Settings →「Pages」→ 新增驗證 `jrf.org.tw`，依指示在 DNS 加一筆 TXT 記錄（主機名稱 `_github-pages-challenge-JRF-tw`），**這筆記錄要一直保留**。沒有驗證的話，如果哪天關掉 Pages 或刪掉儲存庫，而 DNS 還指向 GitHub，別人就能接管 `vote.jrf.org.tw`。（[GitHub 說明](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages)）
- **兩步驟驗證**：組織 Settings →「Authentication security」→ 要求所有成員啟用兩步驟驗證。
- **保護 `main` 分支**：已設定。儲存庫 Settings →「Rules」→「Rulesets」裡的「Protect main」禁止刪除 `main` 和強制覆寫歷史；沒有要求 PR 審核，同仁仍可直接在 GitHub 網頁上修改。有寫入權限的人越少越好（Settings →「Collaborators and teams」）。
- **試算表權限**：試算表裡有民眾的電子郵件，只分享給負責統計的同仁，不要設成「知道連結的人皆可檢視」。

## 第二部分：建立 Google 表單

建議用司改會的公務 Google 帳號建立，方便日後交接。

### 1. 新增表單與題目

1. 到 [forms.google.com](https://forms.google.com) 建立空白表單，標題例如「2026 年度司法大事記（網站專用）」。
2. **第一題：圈選事件**
   - 題型選「**核取方塊**」，題目名稱「圈選事件」，開啟「**必填**」。
   - 選項：打開 `setup.html` 第 2 步，按「複製選項」，回到表單點第一個選項的輸入框貼上，會自動變成 01 到 22 共 22 個選項。
   - 右下角「⋮」→「回應驗證」→ 選「**最多選取**」，數字填 **5**。（表單也要限制最多 5 件。）
3. **第二題：Email**：新增簡答題，不設定格式或電子郵件驗證。網站會把使用者填寫的內容送到這一題。
4. 不要再加其他必填題目，整份表單只使用一個區段。

### 2. 表單設定（很重要，設錯會收不到資料）

點表單上方的「設定」分頁：

| 設定 | 要設成 | 原因 |
| --- | --- | --- |
| 收集電子郵件地址 | **不收集** | Email 透過第二題傳送，不要求登入 |
| 限制回覆次數為 1 次 | **關閉** | 開啟後會要求登入，網站無法直接送出 |
| 僅限貴機構的使用者填寫（Google Workspace 帳號才有） | **關閉** | 會擋掉一般民眾 |
| 允許回覆者編輯回覆 | 關閉 | 避免送出後再改 |
| 傳送回覆副本給填寫者 | 關閉或「應要求」皆可 | 不影響統計 |

最後確認表單右上角的「發布」或「接受回覆」是開啟狀態。

### 3. 連結試算表

表單上方「回覆」分頁 →「連結至試算表」→「建立新試算表」。之後每一筆回覆都會自動出現在這份試算表裡。

## 第三部分：把表單接到網站

1. 在 Google 表單取得預先填入的連結，勾選「01」，並在第二題填入任意文字。
2. 連結中的兩個 `entry.數字` 分別是圈選題與 Email 題的代號。把表單網址結尾 `/viewform` 改為 `/formResponse` 作為接收網址。
3. 在 `assets/config.js` 設定三個值：

```js
googleForm: {
  action: "https://docs.google.com/forms/d/e/表單代號/formResponse",
  picksEntry: "entry.1333646016",
  emailEntry: "entry.2028008171"
}
```

網站使用背景 POST 傳送事件代碼與 Email。Email 只用於這次送出，不存入瀏覽器的 localStorage。

## 第四部分：測試

1. 圈選事件並按「完成我的清單」，應在網站內開啟 Email 視窗。
2. 空白或只有空格時不能送出；送出時檢查基本 Email 格式（例如 name@example.com），格式不符時顯示提示；不驗證信箱是否存在。
3. 實際送出一次，確認表單回覆試算表收到相同的圈選代碼與第二題 Email；不應出現新分頁或 Google 登入畫面。
4. 網路失敗時應保留輸入內容，允許重試；送出期間不能重複點擊。
5. 圈選超過 5 件應被網站阻擋。測試完刪除測試回覆。

網站送出後會記住同一個瀏覽器已投票，重新測試請用無痕視窗。Google 不允許網站讀取跨來源回應，因此背景請求完成不等於已確認入表；實際收到資料須以回覆試算表為準。

---

## 第五部分：在試算表統計結果

1. 在試算表下方按「＋」新增工作表，命名「統計」。
2. 到 `setup.html` 第 2 步按「複製對照表」，貼到「統計」工作表的 A1（會填入 A 代碼、B 事件、C 分類）。
3. 依 `setup.html` 第 5 步，把公式貼到指定儲存格：
   - **D2**：這件事被幾個人圈選，選取 D2 後往下拉到最後一件。
   - **F1**：總共幾個人送出。
   - **E2**：網站用的格式，往下拉。
   - **F2**：合併成一行，公布結果時使用。
4. 可以用 D 欄排序（資料 → 排序範圍）看目前排名。這份試算表請只分享給內部同仁。

## 日常維護

**補圖片**：圖片放進 `images/`（預設建議 3:2、寬 1200px、每張 300KB 以內），在事件的 `image` 填 `"images/2026-01.jpg"`。時間軸也支援長圖比例 `2:3`、`4:5`、`9:16`，以及 `5:4`；非 3:2 圖片請在事件中加上 `imageRatio:"2:3"`（可用值：`3:2`、`2:3`、`4:5`、`5:4`、`9:16`）。引用新聞照片時，同時填 `imageSource:["媒體名稱","原文網址"]`，網站會在圖片上標示「圖／媒體名稱」，並在完整回顧裡附上連結。

**補事件回顧詳細版**：在事件的 `full` 填入文字，換段用 `\n`，例如：

```js
full:"第一段內容。\n第二段內容。",
```

**更新司法民調**：數字改在 `data/polls.js`，並更新最上方的 `updated` 日期。民調頁的開頭提醒和「長期追蹤」說明寫在 `assets/app.js` 的 `pagePolls` 裡，**數字有變動時要一起改**，不然說明會和圖表對不上。

**新聞與時間軸**：每則新聞一行，要指定為重點新聞就加 `key:true`：

```js
{date:"2026/03/25", media:"中央社", title:"新聞標題", url:"https://www.cna.com.tw/……", key:true},
```

- 重點新聞在時間軸上會用紅色粗體醒目標示，事件的發生日期也以它為準。
- 都沒標 `key` 時，以第一則新聞為準。
- 標了兩則以上，這件事會在票選頁時間軸上出現在每個重點日期，第二次以後以灰色精簡卡片呈現，圈選共用。
- 新媒體的標籤顏色在 `data/events.js` 最上方的 `JRF_MEDIA` 新增，沒列到的會顯示灰色。

**截止與公布結果**

1. 截止時間一到，網站會自動停止接受送出；**同時一定要到 Google 表單關閉「接受回覆」**，表單網址是公開的，不關的話截止後仍能直接填。
2. 結果公布、統計確認無誤後，**刪除試算表的電子郵件欄**（或整份回覆），網站上承諾的是公布後刪除。
3. 公布時，打開 `data/events.js` 的 2026 年度，修改三個地方：

```js
status: "closed",
jrfTop: ["07","19","10","04","17","01","12","03","20","05"],   // 司改會評選，依名次排列的事件代碼
final: { voters: 3125, votes: { "01": 812, "02": 640, …… } }    // voters 用「統計」F1 的人數；votes 直接貼「統計」F2 的內容
```

4. 存檔後，「年度結果」和「歷年回顧」會自動顯示「大家心中的年度大事」與「司改會評選」的對照，以及完整排名。

**下一年度（2027）**

1. 在 `data/events.js` 的 `window.JRF_DATA` 裡新增 `2027: { status:"open", jrfTop:null, final:null, events:[ …… ] }`，2026 的資料保留，歷年回顧會自動出現 2027 分頁。
2. `config.js` 的 `year` 改成 2027，並更新 `deadline`、`announce`。
3. 建一份新的 Google 表單，依第二、三部分設定好，把新的 `action`、`picksEntry`、`emailEntry` 填進 `config.js`；舊表單確認已關閉「接受回覆」。
4. `index.html` 的標題、描述和分享文字改成新年度；重做 `images/og-image.png`（圖上印有年份）。
5. `sitemap.xml` 的 `lastmod` 改成更新當天的日期。

**搜尋引擎**：用司改會的 Google 帳號到 [Google Search Console](https://search.google.com/search-console) 新增 `vote.jrf.org.tw`（DNS 驗證），並提交 `https://vote.jrf.org.tw/sitemap.xml`。各分頁用 `#review` 這類網址，Google 會當成同一頁，所以只有首頁會被收錄。

## 常見問題

**送出後試算表沒有資料？**
確認 `action` 結尾是 `/formResponse`，兩個題目代號正確，圈選選項是兩位數代碼；表單須接受回覆，且關閉收集電子郵件、限制回覆 1 次、機構登入限制。不要設定額外的必填題目或 Email 格式驗證。

**網站能確認送出成功嗎？**
Google 不提供跨來源回應，網站只能確認背景請求完成，無法確認資料已寫入。正式使用前務必核對回覆試算表的圈選與 Email 欄位。

**可以防止同一個人重複送出嗎？**
網站記住同一個瀏覽器已送出，但換瀏覽器或用無痕視窗仍可再次投票。Email 未經驗證，不能保證一人一票；統計時可用來協助核對資料。年度結果是參與者的關注排行，不是抽樣民調。

**修改了事件標題，已收到的資料會亂掉嗎？**
不會。表單只記錄事件代碼，標題可以隨時修改。但**不要更改已上線事件的代碼**，也不要刪除表單裡的選項。

**表單選項的順序重要嗎？**
不重要，但選項文字必須和事件代碼完全一樣，網站傳送的代碼才能對應到選項。
