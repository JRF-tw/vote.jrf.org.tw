# 年度司法大事記｜部署與 Google 表單嫁接說明（維護者用）

這份文件給負責維護網站的司改會同仁。網站是純靜態網頁，放在 GitHub Pages（`JRF-tw/vote.jrf.org.tw`，網址 https://vote.jrf.org.tw/）；民眾送出的圈選清單會直接寫進一份 Google 表單，資料由司改會在 Google 試算表裡統計，不對外公開。

> **關於 `setup.html`（表單嫁接小幫手）**：它的「送出測試」按鈕任何人都能按，會往正式表單寫入測試資料，所以已從網站移除。需要時從 git 歷史取回，在自己電腦上雙擊開啟使用，用完**不要 commit**：
>
> ```
> git checkout 368cc01 -- setup.html
> # 用完後
> git rm --cached setup.html && rm setup.html
> ```
>
> 送出改經 Cloudflare Worker 之後，`setup.html` 第 1 步的「目前網站設定檢查」已不適用（表單設定改存在 Worker 的密鑰裡），其他步驟照常使用。

---

## 整體運作方式

```
民眾在網站圈選，通過 Cloudflare Turnstile 人機驗證後送出清單
        │
        ▼
Cloudflare Worker（送出服務）檢查：來源是不是我們的網站、人機驗證是否通過、
圈選內容是否合法（1–5 件、代碼 01–22、不重複）、是否已過截止時間
        │  全部通過才轉送；Google 表單網址只存在 Worker 的密鑰裡，網站上看不到
        ▼
Google 表單收到一筆回覆：「03, 07, 10」
        │
        ▼
Google 試算表自動多一列 → 「統計」工作表即時算出每件事被幾個人圈選
        │
        ▼
結果公布時，把統計結果貼回網站資料檔，網站就會顯示年度排名
```

民眾在網站上看不到即時結果，只會看到自己的清單、關注類型和分享圖卡。

## 第一部分：開啟 GitHub Pages

儲存庫已經在 `JRF-tw/vote.jrf.org.tw`。

1. 儲存庫「Settings」→「General」最下方，把可見度改成 **Public**（免費方案的 GitHub Pages 需要公開儲存庫；網站本來就是公開的，儲存庫裡沒有任何民眾資料）。
2. 「Settings」→ 左側「Pages」：
   - Source 選「Deploy from a branch」。
   - Branch 選 `main`，資料夾選 `/ (root)`，按「Save」。
   - Custom domain 會自動讀到 `CNAME` 檔裡的 `vote.jrf.org.tw`。
3. 請管理 `jrf.org.tw` 網域的人新增一筆 DNS 記錄：`vote` CNAME 指向 `jrf-tw.github.io`。
4. DNS 生效後，回到 Pages 設定勾選「Enforce HTTPS」。
5. `assets/config.js` 的 `siteUrl` 已填 `https://vote.jrf.org.tw/`；若網址改變，記得一起改 `siteUrl`、`CNAME`，以及 `index.html` 的 `og:url`、`og:image`。

> 之後要修改任何檔案：在 GitHub 上點該檔案 →右上角鉛筆圖示編輯 →「Commit changes」，網站約 1 分鐘後更新。

### GitHub 與網域安全設定（請在開啟 Pages 前完成）

能推送到 `main` 的人就能改網站內容，所以要保護的是帳號和網域：

- **驗證網域**：組織 Settings →「Pages」→ 新增驗證 `jrf.org.tw`，依指示在 DNS 加一筆 TXT 記錄（主機名稱 `_github-pages-challenge-JRF-tw`），**這筆記錄要一直保留**。沒有驗證的話，如果哪天關掉 Pages 或刪掉儲存庫，而 DNS 還指向 GitHub，別人就能接管 `vote.jrf.org.tw`。（[GitHub 說明](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages)）
- **兩步驟驗證**：組織 Settings →「Authentication security」→ 要求所有成員啟用兩步驟驗證。
- **保護 `main` 分支**：儲存庫 Settings →「Branches」→ 為 `main` 加保護規則（例如要求 PR 審核）；有推送權限的人越少越好。
- **Enforce HTTPS**：DNS 生效後在 Pages 設定勾選。
- **試算表權限**：Google 試算表只分享給內部同仁，不要設成「知道連結的人皆可檢視」。

## 第二部分：建立 Google 表單

建議用司改會的公務 Google 帳號建立，方便日後交接。

### 1. 新增表單與題目

1. 到 [forms.google.com](https://forms.google.com) 建立空白表單，標題例如「2026 年度司法大事記（網站專用）」。
2. **第一題：圈選事件**
   - 題型選「**核取方塊**」，題目名稱「圈選事件」，開啟「**必填**」。
   - 選項：打開 `setup.html` 第 2 步，按「複製選項」，回到表單點第一個選項的輸入框貼上，會自動變成 01 到 22 共 22 個選項。
   - 右下角「⋮」→「回應驗證」→ 選「**最多選取**」，數字填 **5**。（網站本身已經會擋超過 5 件，這是第二道保險。）
3. 整份表單**只有「圈選事件」這一題、一個區段**。不要加其他題目（例如 E-mail 或關注類型），否則網站送出可能失敗，E-mail 題也會和網站「不蒐集電子郵件」的說明矛盾。
4. **不要把表單連結分享出去。** 表單本身是公開可填的，知道網址的人可以繞過網站和人機驗證直接填。

### 2. 表單設定（很重要，設錯會收不到資料）

點表單上方的「設定」分頁：

| 設定 | 要設成 | 原因 |
| --- | --- | --- |
| 收集電子郵件地址 | **不收集** | 收集信箱需要登入，網站送不進去 |
| 限制回覆次數為 1 次 | **關閉** | 需要登入 Google 帳號，網站送不進去 |
| 僅限貴機構的使用者填寫（Google Workspace 帳號才有） | **關閉** | 同上，會擋掉一般民眾 |
| 允許回覆者編輯回覆 | 關閉 | 不需要 |

最後確認表單右上角的「發布」或「接受回覆」是開啟狀態。

### 3. 連結試算表

表單上方「回覆」分頁 →「連結至試算表」→「建立新試算表」。之後每一筆回覆都會自動出現在這份試算表裡。

## 第三部分：嫁接網站、送出服務與表單

網站不直接送 Google 表單，而是先送到 Cloudflare Worker（免費方案即可），由它檢查後再寫入表單。需要一個 Cloudflare 帳號和一台裝了 Node.js 的電腦。

> **重要：上線前請建一份新的 Google 表單。** 舊表單的網址已經寫在這個儲存庫的 git 歷史裡，儲存庫公開後任何人都查得到，可以繞過 Worker 直接寫入。新表單的網址只放進 Worker 密鑰，不要寫進任何檔案。**舊表單要關閉「接受回覆」或直接刪除**，只建新表單擋不住別人往舊網址送資料。
>
> Cloudflare 帳號請用司改會的公務帳號建立，方便日後交接。

### 1. 取得 Google 表單的兩個值

1. 依文件開頭的方式取回 `setup.html`，在電腦上雙擊開啟。
2. 回到 Google 表單編輯畫面，右上角「⋮」→「**取得預先填入的連結**」。
3. 在跳出的表單裡，「圈選事件」勾選 **01**，按最下方「取得連結」→「複製連結」。
4. 貼到 `setup.html` 第 3 步，會解析出 `action` 和 `picksEntry` 兩個值，先記下來。

也可以手動從連結取出：

```
預先填入的連結：
https://docs.google.com/forms/d/e/1FAIpQLSxxxx/viewform?usp=pp_url&entry.123456789=01
                                 └──────┬──────┘                     └─────┬─────┘
             FORM_ACTION = 把 viewform?… 換成 formResponse            PICKS_ENTRY
```

### 2. 建立 Turnstile 人機驗證

1. 登入 [Cloudflare](https://dash.cloudflare.com/) →「Turnstile」→「Add widget」。
2. Hostname 填 `vote.jrf.org.tw`，Widget mode 選「Managed」。
   - 如果想在 DNS 生效前先用 `jrf-tw.github.io` 測試，Hostname 也要加上 `jrf-tw.github.io`，`worker/wrangler.toml` 的 `ALLOWED_ORIGINS` 也要加 `https://jrf-tw.github.io`，否則 Worker 會拒收。
3. 建立後會拿到兩把鑰匙：**Site key**（公開值，放網站）和 **Secret key**（密鑰，只放 Worker）。

### 3. 部署送出服務

在專案資料夾執行：

```
cd worker
npx wrangler login                       # 第一次使用，會開瀏覽器登入 Cloudflare
npx wrangler deploy                      # 部署，完成後會顯示網址，例如 https://jrf-vote-submit.xxx.workers.dev
npx wrangler secret put TURNSTILE_SECRET # 貼上 Turnstile 的 Secret key
npx wrangler secret put FORM_ACTION      # 貼上 …/formResponse 網址
npx wrangler secret put PICKS_ENTRY      # 貼上 entry.數字
```

`worker/wrangler.toml` 裡的 `ALLOWED_ORIGINS`、`EVENT_COUNT`、`MAX_PICKS`、`DEADLINE` 要和網站一致，改了之後重新執行 `npx wrangler deploy`。

### 4. 把送出服務接到網站

打開 `assets/config.js`，填入：

```js
submit: {
  url: "https://jrf-vote-submit.xxx.workers.dev/submit",   // 部署顯示的網址，後面加 /submit
  turnstileSiteKey: "0x4AAAA……"                            // Turnstile 的 Site key
}
```

## 第四部分：測試

1. **實際網站測試**：等 GitHub 更新後（約 1 分鐘），用手機和電腦各實際圈選、送出一次，確認試算表有收到。
2. **超過 5 件測試**：圈 6 件以上按送出，應該跳出「最多只能圈 5 件」的提醒，且試算表不會多出資料。
3. 測試完，到試算表把測試資料整列刪除（或在表單「回覆」分頁刪除個別回覆）。

> 小提醒：網站已送出的瀏覽器會記住「已送出」，同一個瀏覽器無法再送第二次。要重複測試時，請用無痕視窗。

---

## 第五部分：在試算表統計結果

1. 在試算表下方按「＋」新增工作表，命名「統計」。
2. 到 `setup.html` 第 2 步按「複製對照表」，貼到「統計」工作表的 A1（會填入 A 代碼、B 事件、C 分類）。
3. 依 `setup.html` 第 5 步，把公式貼到指定儲存格：
   - **D2**：這件事被幾個人圈選，選取 D2 後往下拉到最後一件。
   - **F1**：總共幾個人送出。
   - **E2**：網站用的格式，往下拉。
   - **F2**：合併成一行，公布結果時使用。
4. 可以用 D 欄排序（資料 → 排序範圍）看目前排名。這份試算表請只分享給內部同仁。

## 日常維護

**補圖片**：圖片放進 `images/`（建議 3:2、寬 1200px、每張 300KB 以內），在事件的 `image` 填 `"images/2026-01.jpg"`。

**補事件回顧詳細版**：在事件的 `full` 填入文字，換段用 `\n`，例如：

```js
full:"第一段內容。\n第二段內容。",
```

**新聞與時間軸**：每則新聞一行，要指定為重點新聞就加 `key:true`：

```js
{date:"2026/03/25", media:"中央社", title:"新聞標題", url:"https://www.cna.com.tw/……", key:true},
```

- 重點新聞在時間軸上會用紅色粗體醒目標示，事件的發生日期也以它為準。
- 都沒標 `key` 時，以第一則新聞為準。
- 標了兩則以上，這件事會在票選頁時間軸上出現在每個重點日期，第二次以後以灰色精簡卡片呈現，圈選共用。
- 新媒體的標籤顏色在 `data/events.js` 最上方的 `JRF_MEDIA` 新增，沒列到的會顯示灰色。

**截止與公布結果**

1. 截止時間一到，網站會自動停止接受送出；同時請到 Google 表單關閉「接受回覆」。
2. 公布時，打開 `data/events.js` 的 2026 年度，修改三個地方：

```js
status: "closed",
jrfTop: ["07","19","10","04","17","01","12","03","20","05"],   // 司改會評選，依名次排列的事件代碼
final: { voters: 3125, votes: { "01": 812, "02": 640, …… } }    // voters 用「統計」F1 的人數；votes 直接貼「統計」F2 的內容
```

3. 存檔後，「年度結果」和「歷年回顧」會自動顯示「大家心中的年度大事」與「司改會評選」的對照，以及完整排名。

**下一年度（2027）**

1. 在 `data/events.js` 的 `window.JRF_DATA` 裡新增 `2027: { status:"open", jrfTop:null, final:null, events:[ …… ] }`，2026 的資料保留，歷年回顧會自動出現 2027 分頁。
2. `config.js` 的 `year` 改成 2027，並更新 `deadline`、`announce`。
3. 建一份新的 Google 表單，依第三部分取得新的 `FORM_ACTION`、`PICKS_ENTRY`，用 `npx wrangler secret put` 更新。
4. `worker/wrangler.toml` 更新 `EVENT_COUNT`、`DEADLINE`，重新 `npx wrangler deploy`。

## 常見問題

**送出後試算表沒有資料？**
網站會顯示送出失敗的原因。依序檢查：`config.js` 的 `submit.url` 結尾是不是 `/submit`；Worker 的三個密鑰是否都設定了（`FORM_ACTION` 結尾要是 `formResponse`）；`wrangler.toml` 的 `ALLOWED_ORIGINS` 是否包含正式網址、`DEADLINE` 是否正確；表單設定是否關掉了「收集電子郵件」「限制回覆 1 次」「僅限貴機構」；表單是否還在「接受回覆」；表單選項是不是 `01`、`02` 這種兩位數代碼（不能是 `1`、`2`，也不能加標題）；有沒有其他必填題目。

**網站能確認送出成功嗎？**
可以。Worker 會把 Google 表單的回應狀態傳回網站，表單拒收時網站會顯示送出失敗。不過 Google 表單有少數設定錯誤仍會回應成功，所以上線前一定要實際測試、到試算表確認。

**可以防止同一個人重複送出嗎？**
Turnstile 人機驗證可以擋掉程式自動灌票；網站也會記住同一個瀏覽器已送出過，但真人換瀏覽器或用無痕視窗仍可再送。統計時可看試算表的時間戳，留意短時間內大量出現的相同組合。Google 表單的「限制 1 次」需要民眾登入 Google 帳號，會大幅降低參與意願，所以不建議開啟。結果頁與關於頁都已說明，這是參與者的關注排行，不是具代表性的抽樣民調。

**修改了事件標題，已收到的資料會亂掉嗎？**
不會。表單只記錄事件代碼，標題可以隨時修改。但**不要更改已上線事件的代碼**，也不要刪除表單裡的選項。

**表單選項的順序重要嗎？**
不重要，但選項文字必須和事件代碼完全一樣。
